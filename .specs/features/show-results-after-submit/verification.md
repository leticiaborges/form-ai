## Findings (non-blocking, none flips a row)

1. **Level gap, C30-C34 (and the `201`/`400`/`404` members of `Surface`)** - the claims name `400`/`404` (C30-C33) and the plan `Surface` lists `201` for `generate/text` and `400`/`404` for submit and editor, but every proof stops at the exception the handler throws (or, for `201`, the handler outcome in C5/C6). No test anywhere in the repo (unit, integration, e2e) exercises `ExceptionHandlingMiddleware`'s mapping. It is disclosed in `checks.md`, the mapping is a single readable switch (`ExceptionHandlingMiddleware.cs:37-39`), and `git diff 4278f78..HEAD -- src/FormAI.API` is empty, so nothing this feature did could change it; the rows are therefore PASS on what they assert (the throw). Under a strict reading of the rule that a claim naming a status whose proofs sit below the boundary is a level gap, this is one. Fix if wanted: one HTTP assertion per status in the e2e spec (`400` on an expired or invalid submit, `404` on a non-owner PUT); `201` on generate needs a Claude key or a stub.
2. **Precision gap in C28 grep 1** - `grep -q "maximum score" CONTEXT.md` is case-sensitive lowercase and is satisfied by `CONTEXT.md:106` (the "Show score after submit" entry), not by the defining heading `**Maximum score**` at `CONTEXT.md:101`. Deleting the definition would leave that grep green. The definition is present (read at `CONTEXT.md:101-103`), so the claim holds; the proof is weaker than the claim.
3. **C19 is a characterization** - the old inline formula (`form.IsGraded ? Sum(q.Points ?? 0) : null`) satisfies the same equality, so the test would also pass had `FormResultsCalculator` kept its own copy. The claim as written ("equals") is met; the "calls the same function" intent is proven only by reading `FormResultsCalculator.cs:31`.
4. **Generate-route wire binding is unproven over HTTP** - C4 proves the client sends `showResultsAfterSubmit` to `POST /api/forms/generate/text`, and C5/C6 prove the handler honours `request.ShowResultsAfterSubmit`; nothing proves the server binds that JSON key into `GenerateFormRequest` (generation needs a live Claude key). The same key is proven for the editor route by C16. Low risk (positional record, ASP.NET case-insensitive binding) but the door-3 name on this route rests on inference.
